# Bounded readiness recovery

Only `notebooks_paper/coverage_extension.py` orchestration changed. The original frozen manifest, all per-slot configurations, inputs, algorithm code, worker, supervisor, warm-up, validation and phase budgets were retained.

The unchanged readiness function samples host load before each launch. Failed checks enter `waiting_for_host`; short one-second interruptible sleeps place subsequent check starts approximately 30 seconds apart. The existing progress thread writes atomic snapshots every five seconds. Waiting is capped at 900 seconds continuously and 3600 seconds cumulatively per execution session. A complete readiness sampling window is reserved before another check; exhaustion pauses the pending slot without creating a solver attempt. Every readiness measurement/decision remains in its slot. A competing experiment worker is an error requiring investigation, not a host-load retry.

`bounded_wait_execution_amendment.json` records the orchestration hash actually used for all 76 newly executed attempts. `orchestration_before_bounded_wait.txt` preserves the original source. The frozen manifest was not rewritten. After execution, two orchestration edge cases were tightened: reserve 30 seconds before a readiness check even at a new slot when the cumulative allowance is nearly exhausted; distinguish launched/in-progress slots from never-launched pending slots. The current source hash is recorded separately in `bounded_wait_amendment.json`. No optimization was run after these final bookkeeping refinements.

`bounded_wait_checks.json` records simulated-clock checks for failed-check recovery, the 30-second cadence, and both waiting caps, including insufficient cumulative allowance before a new readiness check. Actual host readiness passed throughout the resumed session, so real host-wait recovery was not exercised by this cohort. The execution used 2774.748 seconds of session wall time and zero host-wait seconds.

All 80 slots contain exactly one attempt. Four pre-existing attempts were inherited; 76 were newly executed. Final outcome: 79 validated and one CPS-2F transition-budget exit on AL061921__AL101926. That exit recorded 20,000,001 transition checks, 24,180 discovered states, 18.444 seconds to termination, and 248.551 MiB sampled peak process-tree RSS. It does not establish infeasibility and was not retried.
