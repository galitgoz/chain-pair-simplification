Initial read-only process inspection found the existing Jupyter kernel (PIDs 11420/22664), no experiment worker. Existing files and dependencies were not edited.

## Cohort and scientific definitions
Exactly 32 unique configurations = 4 saved input pairs x 2 alpha values x 4 methods. Identity is (frozen input hashes, pair, alpha, thresholds, method, endpoint policy); repeated attempts at different budgets are not extra scientific configurations.

- Protein 1o7j.a__1d9q.d: 22+22 vertices, angstrom, existing w=16.
- Protein 1o7j.a__1hfj.c: 22+22 vertices, angstrom, existing w=16.
- Hurricane AL031854__AL011991: 25+25 vertices, shared Atlantic projected-km frame.
- Hurricane EP021949__EP031949: 25+25 vertices, shared Pacific projected-km frame.

Use unchanged saved arrays in output/paper_v1/inputs. No resampling, cropping, alignment, greedy preprocessing, approximations, or vertex replacement. Proteins are supplied decimated/subsampled curves, not full-resolution backbones. 1o7j.a is shared between both protein pairs, so the pairs are not independent biological replicates. Manifest gaps and source details remain in graph_only_v1/input_manifest.csv; 1d9q.d has documented geometric gaps. Hurricanes retain all supplied track vertices; upstream filtering/duplicate removal already occurred. No new subsampling or independent alignment. Timestamps are absent; coordinates do not imply temporal synchronization. No storms are shared between the two selected hurricane pairs.

Alpha is 0.5 or 1.0, a dimensionless multiplier of each input's own mean edge length: s_A=mean_i ||A[i+1]-A[i]||, s_B similarly; delta1=alpha*s_A, delta2=alpha*s_B, delta3=d_dF(A,B). Read the exact frozen numerical values in the manifest. Worker configuration JSON is the full-precision authority: earlier CSV serialization/parsing differs by an ulp in some thresholds (e.g. protein delta3 JSON 0.9993252723713152 vs displayed CSV 0.9993252723713151). Do not recompute or round thresholds for reuse. Confirm hash and numeric equality before any future launch; the scientific formula remains unchanged.

Output curves are subsequences of original input vertices, include both endpoints, and have strictly increasing selected indices. Auxiliary points are matching positions only, not selectable output vertices. Unequal output lengths are permitted; a discrete coupling can repeat an index while advancing the other.

| Method | Fidelity | Coupling feasibility | Objective |
|---|---|---|---|
| Independent continuous | Global continuous Frechet(A,A')<=delta1 and global continuous Frechet(B,B')<=delta2 | None; measure output discrete coupling descriptively | Independently minimize each output size; this attains min max(kA,kB) without coupling |
| Independent discrete | Discrete Frechet fidelity on both inputs/outputs | None; a delta3 violation is not failure | Independently minimize each output size; report max(kA,kB) |
| CPS-2F | Global continuous fidelity on each curve | Discrete Frechet(A',B')<=delta3 | min max(kA,kB) |
| CPS-3F | Discrete fidelity on each curve | Discrete Frechet(A',B')<=delta3 | min max(kA,kB) |

Both CPS calls explicitly use certificate=False, disabling independent and alternative certificate returns. The software still computes an independent lower bound as preprocessing, but may not bypass graph search with it. Do not pass the known reference k=5 as a bound or early stop. Global continuous fidelity is not replaced with local shortcut feasibility. Existing shortest_independent computes a local shortcut path solely to bound the number of layers in its global solver; this existing exact upper-bound step is not new greedy preprocessing or a replacement baseline.

Freeze the existing numerical predicates: curve_algorithms.TOL=1e-10, CPS EPS=1e-9, degeneracy squared-length threshold 1e-24; existing continuous sphere/intersection rules and all other predicates unchanged. External discrete checks use +1e-9 and coupling-cost agreement <1e-7; continuous validation calls the existing global decision function. Optional achieved continuous distances are brackets with default absolute tolerance 1e-5, not exact distances. Retain all hash-frozen details rather than homogenizing tolerances.

## Proposed resource policy and actual applicability
All methods: external solver allowance 60 s, sampled sum of worker-tree RSS cap 512 MiB. Separate unchanged phase budgets (seconds): startup 60, input loading/preparation 15, warm-up 120, atomic checkpoint 5, external validation 30, optional measurements 30, reporting 10. New experiment metadata/selection is prepared outside measured solver time. No cache-clearing or system changes.

**Comparability gate:** the literal 800,000-edge policy cannot currently be enforced for independent discrete or throughout CPS-3F by supplying existing configuration fields. This plan does not silently exempt them or alter code. All 16 rows of those methods are flagged policy_exception_resolution_required. Before executing those rows, explicitly decide whether the pilot permits a declared method-specific 2,000,000-edge preprocessing/baseline exception, or separately authorize a reviewed adapter change. This task does neither. The remaining methods can use the proposed policy as written. If the exception is accepted, describe the study as common external resources with declared internal enforcement differences, not fully uniform graph-work caps.

Implementation findings:
- common.solve passes configured graph limits only to solve_cps. Independent discrete calls chain_graph without a max_edges argument; its hidden default is 2,000,000 for EACH curve. Its 55 s/state/transition config values are ignored, not enforced.
- solve_cps computes independent preprocessing before main graphs even with certificates disabled. CPS-3F's preprocessing therefore has the same hidden 2m edge cap. CPS-2F's continuous preprocessing has no explicit edge/state/transition count cap.
- Internal CPS time starts before preprocessing but is checked only after processing a nonterminal product state; chain construction and long inner loops have no internal timeout checks. The external supervisor is the enforcement backstop. finish() can also exceed the soft time between checkpoints.
- State limit tests len(values)>=cap before creating a new product state. It bounds discovered product-state keys, not memory consumed by every cost label/predecessor. Transition count increments after non-self/coupling-allowed filtering, before count-label updates; the 20,000,001st counted transition triggers a 20m exit. This is not all nested candidate pairs or all DP operations.
- Single-chain edge caps count generated edges before pruning; reported post-pruning edge totals are not the budget counter. Generation stops after cap+1. Auxiliary generation has no standalone count cap; time/RSS still apply.
- External monitoring nominally sleeps 0.05 s and samples all owned descendants. Scheduling can delay samples and termination. RSS is approximate process-tree resident memory, not exact algorithm memory or a guaranteed instantaneous cap. Do not relabel memory/timeout exits as mathematical infeasibility.

## Execution, timing and validation boundaries
Use existing graph_only_v3 worker/supervisor/common. Sequence: input loading, separate warm-up, solving, immediate atomic raw checkpoint, external validation, optional measurements, reporting. Warm-up remains the three-vertex synthetic input with each relevant method and distance predicates; internal warm-up time is unlimited within its 120 s external cap. It uses the existing synthetic graph defaults (30k states, 500k transitions, 200k chain edges), not the experiment budgets. Each new execution uses its own initially empty output-local Numba/Matplotlib cache; do not clear historical caches. OPENBLAS_NUM_THREADS=1 and OMP_NUM_THREADS=1; record any other thread settings, Python executable/version/hash, packages, platform and code hashes.

No concurrent experiment workers. Before launch, sample host CPU, available memory and competing processes for about 20 s. Inspect complete per-process samples rather than one average cutoff; defer without indefinite waiting if sustained CPU-intensive work or inadequate memory remains. Record the readiness decision, including no-launch events. Host observations do not prove causes of past slowdowns. No changes to system settings or termination of unrelated processes.

The successful raw checkpoint must preserve selected original indices, kA/kB/k, claimed status, route, counters, configuration/input/code hashes, elapsed solving time and all limits. Save before external validation. CPS success requires certificate_enabled=False, graph-entry/completion evidence and optimal_configuration_graph. Existing solver finish() performs internal endpoint/order/fidelity/coupling checks before returning; these remain in solver time. Independent continuous also internally verifies global fidelity; independent discrete does not use finish(). External validation gets its own timer and budget and checks membership, bounds/order, endpoints, counts/objective, applicable fidelity and coupling. Independent outputs need not satisfy delta3.

Feasibility validation is not an independent optimality proof. Preserve solver claims separately and cite prior exhaustive small-instance correctness checks (v1 100 checks; v2 21 orchestration/regression checks) with their saved provenance, not as a new run. Incomplete/failed validation excludes the result from quality tables but never deletes raw output. Optional measurement failure is separate. Save exact resource/phase and available counters when no solution returns; missing objectives stay missing. Original curves are feasible at the frozen delta3, so any mathematical infeasibility claim requires investigation.

This interleaves methods across blocks instead of running every easy/favorable result first. Honor selected reuse slots without executing them. Do not start flagged exception rows until policy resolution; otherwise visit pending slots in plan_order, one worker at a time. No larger cohort or budget sweep.

Strict plan: 31 new solver slots x 60 s = 1,860 s (31 min) nominal solver allowance; separately allocated phase ceilings sum to 330 s per attempt, giving 170.5 min for 31 attempts plus readiness (~10.3 min if 20 s per slot). This is a conservative planning envelope, not a runtime prediction or exact wall bound: supervisor sampling can overshoot and readiness may defer work.
